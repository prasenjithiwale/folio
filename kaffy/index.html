kaffy

A terminal UI for exploring and operating Kafka clusters. Follow messages live, jump to any offset or time, read Avro and Protobuf through your Schema Registry, keep an eye on consumer lag, and manage schemas and topics. For Linux and macOS.

curl -fsSL https://prasenjithiwale.github.io/folio/kaffy/install.sh | sh
brew trust --formula prasenjithiwale/tap/kaffy && brew install prasenjithiwale/tap/kaffy

Latest release v0.1.0, . Linux (x86_64, arm64) and macOS. Other ways to install · Source on GitHub

See it run

Recorded in kaffy --demo: open a topic from the command palette, filter it to paid or shipped orders on two partitions, read one message, check a stopped consumer group's growing lag, preview an offset reset without applying it, and diff two versions of an Avro schema. Also available as a GIF.

Install

The install script picks the build for your system, downloads the latest release, checks its SHA-256 checksum and puts kaffy in ~/.local/bin. It works with sh and bash, on Linux and macOS.

curl -fsSL https://prasenjithiwale.github.io/folio/kaffy/install.sh | sh

Homebrew

On macOS or Linux, install from the prasenjithiwale/tap tap. Homebrew loads formulae from other people's taps only once you trust them, which is the first command:

brew trust --formula prasenjithiwale/tap/kaffy && brew install prasenjithiwale/tap/kaffy

Then brew upgrade kaffy picks up new releases.

Options

Set these before sh to change what the script does:

curl -fsSL https://prasenjithiwale.github.io/folio/kaffy/install.sh | KAFFY_VERSION=v0.4.1 KAFFY_INSTALL_DIR=/usr/local/bin sh
KAFFY_VERSION
Install a specific release instead of the latest.
KAFFY_INSTALL_DIR
Where to put the binary. Defaults to ~/.local/bin; a system directory may need sudo sh.

Requirements

Linux on x86_64 or arm64, any distribution: the binary is static, so Alpine and older systems work too. macOS 11 or newer, on Apple Silicon or Intel.

    Uninstall

    Delete the binary: rm ~/.local/bin/kaffy, or brew uninstall kaffy if Homebrew installed it. kaffy keeps its config in ~/.config/kaffy and its log in ~/.cache/kaffy.

    Get started

    Try it without Kafka

    kaffy --demo runs against a built-in fake cluster with live data, including Avro messages, a small Schema Registry and topic configs.

    Connect to a broker

    kaffy --bootstrap localhost:9092 connects without any setup. Add --schema-registry http://localhost:8081 to decode Avro, JSON Schema and Protobuf.

    Save your clusters

    Describe clusters in ~/.config/kaffy/config.toml, then pick one with kaffy --profile staging. Profiles support SSL, mutual TLS and SASL (PLAIN, SCRAM), and read passwords from environment variables rather than the file.

    [profiles.staging]
bootstrap_servers = "broker-1.staging:9094"
security_protocol = "sasl_ssl"
sasl = { mechanism = "SCRAM-SHA-512", username = "svc-kaffy", password_env = "KAFFY_STAGING_PASSWORD" }
schema_registry = { url = "https://schema-registry.staging:8081" }

    Cloud clusters

    Confluent Cloud works with an API key over SASL/PLAIN. Amazon MSK with IAM access control needs only the region; kaffy signs the tokens with your AWS credentials, including SSO and assumed roles through the AWS CLI:

    [profiles.msk]
bootstrap_servers = "b-1.mycluster.abc123.c2.kafka.eu-west-1.amazonaws.com:9098"
security_protocol = "sasl_ssl"
aws_msk_iam = { region = "eu-west-1", profile = "msk-dev" }

    Protobuf without a registry

    For topics carrying plain Protobuf, point a profile at the .proto files. kaffy compiles them itself, so protoc isn't needed.

    [[profiles.staging.protobuf]]
topic = "orders-proto"
files = ["proto/orders.proto"]
include = ["proto"]
value = "acme.Order"

    Using kaffy

    Keys on the messages screen, and the other screens
    /Filter messages
    spacePause or resume the live tail
    b eRead from the beginning, or only new messages
    o tJump to an offset, or to a time such as -15m
    enterOpen a message
    y YCopy the value or key
    p EProduce a message, or edit this one and produce it
    KProduce a tombstone for this key
    XReplay messages into a topic
    xExport the shown messages
    1Topics, where c shows the config, n creates a topic, D deletes one and T deletes records
    2Consumer groups, where R resets offsets
    4Brokers and partition health
    :Command palette: run a command or jump to a topic, group or subject
    3Schemas, where d diffs versions, e edits and n registers a new subject
    ?All keys of the current screen
    escGo back

    Make it yours

    kaffy has dark and light themes, and uses your terminal's 16 colors where true color isn't available. Pick one with --theme or theme = "light" in the config. Any key can be rebound in a [keys] table, and the help and footer show your keys:

    [keys]
pause = "p"
produce = "P"

    Filter examples

    cust-042
    Key or value contains the text, ignoring case.
    ~"status":"(PAID|SHIPPED)"
    Key or value matches a regular expression.
    key:cust- h:trace-id
    Search only the key, value (value:) or headers.
    p:0,2 after:-1h
    Partitions 0 and 2, from the last hour. before: works too.
    !cancelled
    Leave out matching messages.

    Making changes

    Every change shows exactly what will happen and waits for y. On profiles marked prod = true you type the group or topic name instead. Profiles are read-only unless you set read_only = false, and kaffy never joins a consumer group just to read, so browsing moves no one's offsets.

    Reset offsets
    Move a stopped consumer group to the earliest or latest offset, a point in time, or a specific offset. The preview shows how many messages will be processed again or skipped.
    Produce
    Write a message in your $EDITOR: key, headers, partition and value. Editing an Avro message keeps it Avro.
    Replay
    Copy a range of messages, by offset or time, into the same or another topic. The current filter applies, so you can replay only the messages you are looking at.
    Schemas
    Edit the latest schema of a subject in your $EDITOR, or start a new Avro, JSON Schema or Protobuf subject. kaffy checks compatibility with the registry, shows the diff, and registers only when you confirm.
    Topics
    Create and delete topics, and change their configs. kaffy reads the config back to confirm a change took effect.
    Delete records
    Remove everything before an offset or a time. Like deleting a topic, this can't be undone, so it always asks you to type the topic name, on every profile.
    Tombstones
    Produce a null value for a message's key, which deletes the key on compacted topics.
    Export
    Save the shown messages as JSON, NDJSON or CSV. Works on read-only profiles too.

    Try all of it safely with kaffy --demo, whose fake cluster accepts changes.
